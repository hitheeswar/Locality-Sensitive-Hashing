01 // Introduction

The Curse of Dimensionality

Imagine you're building a music recommendation system. Every song is described by thousands of audio features — tempo, timbre, pitch distribution, harmonic complexity. When a user plays a song, you want to find the 10 most similar songs out of a library of 50 million tracks. The naive approach — compute the distance between the query song and every single track — is hopelessly slow at scale. This is the nearest-neighbor problem.

As the number of dimensions grows, traditional data structures like k-d trees and ball trees break down. The volume of the space grows exponentially, points become uniformly sparse, and every point ends up roughly equidistant from every other. This phenomenon is the infamous curse of dimensionality.

💡 Key Insight

Locality Sensitive Hashing (LSH) sidesteps the curse of dimensionality by sacrificing exactness for speed. Instead of finding the exact nearest neighbor, it finds an approximate one — fast enough to work on billions of items in real time.

LSH was introduced by Indyk and Motwani in 1998 and has since become a cornerstone technique in large-scale machine learning, information retrieval, and bioinformatics. The core idea is elegant: design hash functions that map similar items to the same bucket with high probability, and dissimilar items to different buckets.

What Makes LSH Different from Regular Hashing?

A regular cryptographic hash function (like SHA-256) deliberately destroys structure: a tiny change in input produces a completely different hash. That's great for security, terrible for similarity search. LSH does the opposite — it preserves proximity. Points that are close together in the original metric space are likely to collide (hash to the same value), while distant points are not. This is the defining property that makes LSH powerful.

02 // Mechanism

How LSH Works

LSH is best understood through a precise probabilistic contract. A hash function family H is said to be (r₁, r₂, p₁, p₂)-sensitive for a distance function D if for any two points x, y:

If D(x,y) ≤ r₁  ⟹  Pr[h(x) = h(y)] ≥ p₁
If D(x,y) ≥ r₂  ⟹  Pr[h(x) = h(y)] ≤ p₂
Where p₁ > p₂ and r₁ < r₂

In plain English: nearby points collide often, far-away points rarely do. The ratio p₁/p₂ is the amplification quality — the higher it is, the more discriminative the hash family.

The Three-Phase Pipeline

01

Shingling / Featurization

Convert raw data (text, images, audio) into high-dimensional vectors or sets. For documents this might be character n-grams (shingles); for images, pixel embeddings or CNN features.

02

Hashing with an LSH Family

Apply g = k independent LSH functions from the chosen family to each item. Each group of k functions forms a "band". Items that agree on all k values in a band are candidate pairs for that band.

03

Amplification via Banding

Repeat with b independent bands, each of width k. A pair becomes a candidate if it matches in at least one band. Tuning b and k trades off recall vs. precision.

04

Candidate Verification

Compute exact distances only for candidate pairs. Since the number of candidates is a tiny fraction of all pairs, this step is fast even with an expensive distance measure.

Banding and the S-Curve

With b bands and k rows per band, the probability that two items with underlying Jaccard similarity s become candidates is:

P(candidate) = 1 − (1 − sk)b
This creates a characteristic S-curve in similarity space

The inflection point of the S-curve sits near s* = (1/b)^(1/k). By choosing b and k appropriately, you can make this curve very steep — almost a step function — which maximally separates near-duplicates from truly dissimilar pairs.

03 // Hash Families

LSH Families for Different Metrics

The choice of LSH family must match the similarity metric you care about. There is no universal LSH hash family — each is tailor-made for a specific notion of closeness. The three most widely used are:

MinHash — Jaccard Similarity

MinHash is designed for set-based similarity (Jaccard). Given a universal set U and a random permutation π of U, the MinHash of a set S is defined as the minimum element of π(S). The remarkable property is that the probability of two sets having the same MinHash equals their Jaccard similarity:

Pr[hπ(A) = hπ(B)] = |A ∩ B| / |A ∪ B| = J(A, B)
One random permutation provides one unbiased estimator of Jaccard similarity

In practice, rather than computing actual random permutations (expensive), we use random hash functions h(x) = (ax + b) mod p mod n over integers to simulate permutations. With n MinHash functions, the signature of a document is an n-dimensional vector of integers that can be compared cheaply.

SimHash — Cosine Similarity

SimHash (also called Random Hyperplane LSH) targets cosine distance. For each random unit vector r, the hash bit is 1 if r·x ≥ 0, else 0. The probability that two vectors x and y produce the same bit equals 1 minus their angular distance divided by π:

Pr[hr(x) = hr(y)] = 1 − θ(x,y) / π
θ(x,y) is the angle between vectors x and y

SimHash is the technique behind Google's near-duplicate web page detection. A 64-bit SimHash signature is computed per page, and pages with Hamming distance ≤ 3 on their signatures are treated as near-duplicates. This enables deduplication across the entire crawled web at low cost.

Random Projection LSH — Euclidean Distance

For Euclidean (L₂) distance, we use a hash function based on random projections with a quantization step:

ha,b(x) = ⌊ (a · x + b) / w ⌋
a is a random Gaussian vector, b is uniform in [0,w], w controls bucket width

The parameter w controls granularity: small w gives narrow buckets (high precision, low recall), large w gives wide buckets (high recall, lower precision). This family is proven (r₁, r₂, p₁, p₂)-sensitive for appropriate parameter choices.

04 // Implementation

Building LSH from Scratch

Here is a clean Python implementation of MinHash-based LSH for document similarity detection. This is the same core logic used by Apache Spark's MLlib and the datasketch library.

Python 3 
import numpy as np
from collections import defaultdict

class MinHashLSH:
    """MinHash LSH for approximate Jaccard similarity."""

    def __init__(self, num_hashes=128, num_bands=32, rows_per_band=4):
        self.num_hashes    = num_hashes    # total signature length
        self.num_bands     = num_bands      # b: number of bands
        self.rows_per_band = rows_per_band  # k: rows per band
        self.buckets       = [defaultdict(list) for _ in range(num_bands)]
        self._init_params()

    def _init_params(self):
        # Universal hash params: h(x) = (ax + b) mod p mod n
        p = 2_147_483_647  # Mersenne prime
        self.a = np.random.randint(1, p, self.num_hashes)
        self.b = np.random.randint(0, p, self.num_hashes)
        self.p = p

    def minhash_signature(self, doc_set):
        """Compute MinHash signature for a set of integer shingles."""
        sig = np.full(self.num_hashes, np.inf)
        for x in doc_set:
            hashes = (self.a * x + self.b) % self.p
            sig = np.minimum(sig, hashes)
        return sig.astype(int)

    def index(self, doc_id, shingles):
        """Add a document to the LSH index."""
        sig = self.minhash_signature(shingles)
        for band_idx in range(self.num_bands):
            start = band_idx * self.rows_per_band
            end   = start + self.rows_per_band
            bucket_key = tuple(sig[start:end])
            self.buckets[band_idx][bucket_key].append(doc_id)

    def query(self, shingles, threshold=0.5):
        """Return candidate IDs with Jaccard similarity above threshold."""
        sig = self.minhash_signature(shingles)
        candidates = set()
        for band_idx in range(self.num_bands):
            start = band_idx * self.rows_per_band
            end   = start + self.rows_per_band
            bucket_key = tuple(sig[start:end])
            candidates.update(self.buckets[band_idx].get(bucket_key, []))
        return candidates

# ── Example Usage ────────────────────────────────────────
def shingle(text, k=3):
    """Convert text to a set of character k-gram hashes."""
    return {hash(text[i:i+k]) for i in range(len(text) - k + 1)}

lsh = MinHashLSH(num_hashes=128, num_bands=32, rows_per_band=4)

docs = {
    0: "the quick brown fox jumps over the lazy dog",
    1: "the quick brown fox leaps over a lazy dog",  # near-dup
    2: "locality sensitive hashing is a useful technique",
}

for doc_id, text in docs.items():
    lsh.index(doc_id, shingle(text))

query_text = "the fast brown fox jumps over the lazy dog"
candidates = lsh.query(shingle(query_text))
print(f"Candidates: {candidates}")  # → likely {0, 1}

Index N items — O(N · d · b·k)
Query (find neighbors) O(N · d) O(d·b·k + |candidates|)
Space O(N · d) O(N · b · k)

d = dimensionality, b = number of bands, k = rows per band, N = corpus size

05 // Applications

Where LSH Powers the Real World

LSH isn't just an academic curiosity. It underlies systems you interact with every day:

🔎

Near-Duplicate Detection

Google uses SimHash to identify duplicate and near-duplicate web pages during crawling, preventing index bloat.

🎵

Music & Media Fingerprinting

Services like Shazam and YouTube's Content ID use audio fingerprinting algorithms closely related to LSH to match clips against massive libraries in milliseconds.

🛍️

Recommendation Systems

Collaborative filtering at scale (Spotify, Netflix, Amazon) uses LSH to find similar users or items without comparing all pairs.

🧬

Genomics

MinHash-based tools like MASH compare genome sequences at the read level, enabling rapid species classification and metagenomics.

🖼️

Image Deduplication

Perceptual hashing (pHash) combined with LSH deduplicates image datasets at the scale of billions of photos.

🤖

Vector Database Search

Modern vector DBs (Pinecone, Weaviate, Milvus) use LSH variants alongside HNSW graphs to serve embedding search for LLM applications.

LSH in the Age of Large Language Models

With the explosion of embedding-based retrieval (RAG — Retrieval Augmented Generation), approximate nearest neighbor search has become mission-critical. When a user asks a question, a language model retrieves relevant text chunks from a knowledge base by finding vectors close to the query embedding. LSH enables this at production scale across millions of document chunks without requiring expensive GPU-based exact search.

⚡ Performance Benchmark

On a corpus of 10 million 768-dimensional embeddings, LSH-based ANN search runs in ~2ms per query with ~90% recall, compared to ~4,000ms for brute-force exact search. A 2,000× speedup with only a 10% accuracy trade-off.

06 // Limitations

Trade-offs & Limitations

LSH is not a free lunch. Understanding its failure modes is as important as understanding its strengths:

⚠

No Exact Guarantees

LSH can miss true nearest neighbors (false negatives) and return non-neighbors as candidates (false positives). For applications requiring exact results, a post-verification step is needed.

⚠

Parameter Sensitivity

Performance is highly sensitive to the choice of b (bands) and k (rows per band). Poor choices lead to either too many false positives or too many missed neighbors. Tuning requires knowledge of the data distribution.

⚠

Memory Overhead

Maintaining b × buckets uses significant memory for large corpora. Hash table collisions in dense buckets can degrade query time.

⚠

High-Dimensional Regimes

In very high dimensions (>10,000), random projections become less stable and the gap between p₁ and p₂ shrinks, reducing discriminative power.

Modern Alternatives and Complements

In recent years, graph-based ANN algorithms like HNSW (Hierarchical Navigable Small World) and tree-based methods like Annoy have challenged LSH on pure recall-QPS trade-off benchmarks. However, LSH retains advantages in streaming/online settings, sublinear space, and theoretical guarantees. Hybrid approaches combining LSH for fast candidate generation with HNSW for refinement are increasingly popular in production systems.

07 // Summary

Key Takeaways

📌 TL;DR

Locality Sensitive Hashing is a probabilistic technique for approximate nearest-neighbor search that hashes similar items to the same bucket with high probability. By choosing the right hash family (MinHash for Jaccard, SimHash for Cosine, E²LSH for Euclidean) and tuning the banding parameters, you get sub-linear query time with controllable accuracy. It powers near-duplicate detection, recommendation systems, genomics, and embedding-based AI search at massive scale.
